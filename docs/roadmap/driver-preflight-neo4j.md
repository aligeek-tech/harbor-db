## Behavior, bounds and failure semantics

Dedicated Cypher workspace provides explicit execution, typed parameters, paged table results, bounded SVG graph, node/relationship properties and reviewed mutations. Preparing a one-hop expansion only fills a query limited to 50 rows; the user explicitly runs it. No automatic data query, result persistence or query history is introduced. Database/query controls are locked while a cursor is open; each result identifies its database.

Parameters preserve signed 64-bit integers and supported temporal precision, finite floats, points and nested typed values. Dates/datetimes/durations are native driver values. Nested JSON integer tokens stay exact. Returned native Nodes, Relationships, Paths, temporal and spatial values retain type labels, IDs and properties; unsafe integers never pass through JavaScript Number. Parameters are limited to 100 entries / 1 MiB combined text, bounded depth and value complexity. Each decoded cell has a 1 MiB serialization bound. These are application bounds after driver decoding, **not a guarantee that the driver never allocates a larger single server value**.

A page has at most 100 read rows (UI default 25); the entire read execution stops at 1,000 rows or 8 MiB serialized rows. The graph draws at most 200 nodes and 400 relationships per page, with explicit truncation. At most two live query sessions per connection; a UUID cursor is bound to that live session and rotated at each page. Pagination consumes the same driver iterator without rerunning Cypher. Native read-committed isolation is not snapshot isolation. Overall execution/cursor lifetime is the configured query deadline, capped at 60 seconds.

Read mode combines a conservative single-statement lexical guard with native READ access mode. The guard intentionally rejects procedures, external loading and administration; it may reject safe queries using reserved tokens. It is not a general Cypher parser or a replacement for server privileges. Mutation mode requires a writable profile and exact connection/database target confirmation. It consumes the complete result before COMMIT; exceeding 500 returned mutation rows rolls back. A returned-row bound does not limit the count of affected entities: users must review the complete Cypher and parameters. No mutation is retried.

Cancellation closes the execution's dedicated driver sockets, so other query sessions remain usable. A local rejection race is necessary because the SDK can otherwise leave a waiting keys/iterator promise unresolved after transport closure. Cleanup is bounded. Cancellation reports that server cleanup is not acknowledged; it does not claim authoritative rollback. Before commit, error recovery first discards the paused iterator and awaits native rollback for at most three seconds; only an acknowledged rollback is reported as such. Once COMMIT is dispatched, explicit Cancel is declined. A lost commit acknowledgment is uncertain and must be independently reconciled; no replay occurs.
