## Implemented behavior and limits

Profile selection defines account and region; expected AWS account and region are checked against DescribeTable ARN before item requests. ListTables connection success by itself does not attest account identity. Catalog names page at 100 entries without automatic traversal. Table metadata identifies partition/sort keys, global/local indexes, table status, capacity mode and configured capacities. Query is the default and requires exact native partition-key type, with optional bounded sort-key condition/order. Scan has a separate mode and explicit unchecked capacity consent. GSI strong consistency is rejected. No automatic item query or full-table scan occurs on connect or table selection.

Native JSON preserves S/N/B/BOOL/NULL/SS/NS/BS/L/M, exact number strings, canonical base64 and nested maps/lists. Duplicate JSON keys fail; depth is at most 32 and value complexity at most 50,000. Attribute source text is capped at 1 MiB; serialized requests at 1 MiB. Raw HTTP bodies are stopped at 8 MiB before SDK deserialization. The first overflowing chunk can exist transiently; no claim of zero-copy decoding is made.

Each read evaluates at most 100 items per page (UI 25), with a traversal cap of 10 pages / 1,000 evaluated items / 8 MiB serialized displayed items. Native LastEvaluatedKey stays only in main process behind rotating UUID cursors bound to profile/session/input and table identity. Table ARN plus creation time are rechecked before the next page. Cursor lifetime is 10 minutes; admission counts pending requests toward a maximum of 20 cursors. At most four requests per connection and one per workspace; each request deadline is capped at 60 seconds. Native Limit counts evaluated items, not whole-table cardinality. No snapshot consistency is claimed. Raw consumed-capacity data is shown per request; local capacity is not represented as a billed AWS measurement.

Writes are one item, explicit mode and exact connection/table confirmation, with both IPC and service read-only guards. Create uses native attribute_not_exists on the partition key and requires the full primary key in the supplied item. Patch uses native SET/REMOVE for named non-key fields. Patch/delete require expected native attribute equality or expected absence and an existing key. Native conditions are atomic; they protect **only named attributes**, not the entire item. Delete removes all current item attributes if those conditions match. UI recommends an application version attribute when whole-item concurrency control is required. No batch, transaction, table administration, PartiQL or unguarded replacement surface is introduced.

Submitted writes are never retried. ConditionalCheckFailedException is a definitive unchanged-item conflict; the draft remains visible for review. Lost response/abort/unknown failures after write submission report uncertainty and require independent item inspection. Read cancellation aborts the local HTTP request and permits explicit subsequent work; it does not claim service-side cancellation. Profile disconnect/close aborts active requests and clears cursors. Drafts/results/typed item data are component state and not persisted as query history.
