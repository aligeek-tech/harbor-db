# CouchDB 3.5 document workflow

## Dependency and fixture preflight

No additional npm runtime dependency. Uses Node 24 HTTP/HTTPS, the existing lossless-json 4.3.1 parser and the shared verified SSH/TLS transport. The separate protocol class does not alter the search adapter. CouchDB and its [official image source](https://github.com/apache/couchdb-docker) use Apache-2.0. The pinned local fixture is CouchDB 3.5.1, native ARM64, verified by actual server greeting and authenticated session. No latest-version or hosted-service claim is made.

`compose.couchdb.yaml` pins index `sha256:ccea1e8035bf7afd68336e24056a1ca9c1c46d7abe42da686322c0ac7218e5c2`, ARM64 child `sha256:b7176956426645f7ab91cfb0673d6fa791c548e69ecb0bdcd31c2322b82459b7`. Unique project `harbor-roadmap-couchdb-y6pr0dek`, loopback 15984, one CPU, 512 MiB, 256 PIDs, bounded logs and a separate named data volume. External mode-0600 credentials are required. Single-node configuration has n=1 and authenticated access. Initial root startup failed silently when its entrypoint attempted ownership changes on a read-only config mount; running as the image's native UID 5984 corrected it. The server and volume were not reset. Fixture stopped after native acceptance to release capacity for Neo4j; retained data remains disposable.

## Implemented scope and boundaries

The connection form uses exact endpoint/database and Basic authentication. TLS requires certificate and hostname verification; redirect following, compressed responses and automatic request retries are disabled. Arbitrary URLs, proxies and external authentication providers are not supported. Direct HTTPS through a local TLS termination proxy was verified; combined shared SSH transport is implemented but has no separate CouchDB-specific runtime acceptance.

The dedicated document workspace does not execute a selector on open. Users choose a database or enter its exact name if server listing permissions are unavailable. Mango reads require explicit Run; index fallback and potentially expensive scans require an unchecked-by-default consent control. Queries have at most 100 documents per page and 8 MiB per HTTP response; individual editable documents and requests are limited to 1 MB. Opaque ten-minute pagination tokens bind the live connection, session, exact selector, database, index, consent and page size. Changed queries, consumed tokens and reconnects cannot reuse prior bookmarks. Twenty cursor tokens and four concurrent reads per connection bound retained state. Pages are not a database snapshot; concurrent writes can affect subsequent results. [Mango API and bookmark semantics](https://docs.couchdb.org/en/stable/api/database/find.html)

Lossless JSON decoding preserves native numeric text and nested values. Whole-document create/replace and revision-aware delete require typed target/action/revision confirmation. Read-only profiles reject writes in the main process, independently of server permissions. Replacements also check current revision, attachments and sibling conflicts before submitting; CouchDB's `_rev` comparison is the authoritative atomic conflict check. Stale drafts remain visible in the renderer. No write is replayed, and transport failure after dispatch is reported as potentially uncertain. Deleting a reviewed revision may expose a sibling conflict, explicitly disclosed in the UI. Document IDs beginning with underscore, system databases, design writes, attachments editing, replication administration and automatic conflict merging are excluded. Sibling conflict IDs and attachment names remain visible; exact sibling revisions can be read by the API. [Native revision and conflict behavior](https://docs.couchdb.org/en/stable/replication/conflicts.html)

Cancel closes only the matching read's local request; server completion is not guaranteed. Closing tabs/connections invalidates cursor state. No document content, result, mutation or credential is persisted in bootstrap/history by this workspace. Restart restores only existing workspace metadata; no query runs automatically.
