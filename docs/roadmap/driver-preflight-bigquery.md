## Implemented candidate

The fixed verified-TLS Google API endpoint uses a user-supplied OAuth access token stored only through the existing credential service. No ambient account discovery, service-account files, automatic login/refresh, SSH, cloud provisioning or data transfer occurs by default. Expired/rejected tokens require explicit replacement. Connect checks dataset metadata on the explicitly selected project; database navigation maps to projects, schemas to datasets, objects to native tables/views/materialized views. Metadata listing is bounded and never submits data queries.

Table opening creates an inert GoogleSQL draft. Each query submission requires review of project/location/maximum billed bytes and the exact profile name. An explicit dry-run button estimates the full draft without executing it (parameter values are not included in that button). Query jobs bind named values through native fields, attach a stable generated native job ID, set a byte cap/job deadline, poll native state and page results with bounded memory. Display row limits do not limit billed scans. Full export explicitly reruns a read-only job with the same billing controls and backpressure. Cancellation is best effort, never reverses completed writes/billing, and is never followed by resubmission. A lost submission acknowledgement still retains the generated ID for attempted cancel and external outcome inspection.

Native INT64/BIGNUMERIC/temporal text, canonical typed nested records/repeated values, NULL/empty, binary and duplicate columns remain exact. TIMESTAMP result metadata explicitly identifies native epoch-seconds text instead of guessing a timezone or converting to JavaScript Date. Decimal parameters accept a conservative plain 38-integer/38-fractional-digit range and reject rounding-prone input. No interactive transactions, row editing, scripts/session state, native file import, automatic account refresh or unrelated Cosmos/Firestore support is advertised.

## Verification and blockers

`implementation-bigquery-protocol`: six unit/protocol tests pass, exit0. These use an explicitly injected endpoint and prove local request construction, exact conversion, job/session scoping, billing review, no write replay, dry-run separation, expired-token classification and endpoint/readonly guards only. They **do not prove BigQuery compatibility**. UI wiring, typecheck and combined build are being checked independently.

Real BigQuery and actual desktop verification remain blocked by an authorized disposable Google Cloud project/dataset in a specified job location, a short-lived token with BigQuery job/read permissions, a separately restricted account, an explicit test billing budget, and synthetic fixture tables. No suitable credentials or project have been supplied; existing machine/cloud accounts have not been inspected or used. Obtain these through secure local configuration rather than pasting secrets into chat. No cloud resource or billable query has been created by this task. The ticket is implemented-candidate with real-service acceptance incomplete, not an advertised verified support badge.
