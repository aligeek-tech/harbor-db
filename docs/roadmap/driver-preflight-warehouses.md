# Snowflake and Databricks SQL — candidate support, real services unverified

DB09 and DB14 preflight, 2026-09-18. The implementation uses the documented native APIs independently; no PostgreSQL protocol adapter or universal compatibility assumption is involved. No provider SDK/native module is redistributed, and no new dependency is required. Existing exact JSON and Node HTTPS handle transport.

Official references inspected: [Snowflake SQL API authentication](https://docs.snowflake.com/en/developer-guide/sql-api/authenticating), [request/response API](https://docs.snowflake.com/en/developer-guide/sql-api/reference), [exact result types, partitions and gzip](https://docs.snowflake.com/en/developer-guide/sql-api/handling-responses), [Databricks statement lifecycle](https://docs.databricks.com/api/statement-execution/v1/statement-execution), [Databricks SQL warehouse state](https://docs.databricks.com/api/warehouses/v1/get-warehouse).

## Workflows

Snowflake: explicit account endpoint, warehouse name, optional role, database/schema, supplied OAuth/PAT/already-generated key-pair JWT. Native version probe, databases/information-schema objects/columns, one reviewed SQL statement, asynchronous native handle, bounded exact partitions (including bounded gzip decoding), cancellation and separate full read-only export. Temporal output uses explicit nanosecond formats and UTC session settings; binary is native hex decoded exactly into tagged bytes. Numeric and variant text retains native type metadata. No automatic browser login, JWT signing, credential refresh, interactive transaction, parameter binding or row editing is advertised.

Databricks: explicit official AWS/Azure/GCP workspace hostname, already-existing SQL warehouse ID, supplied scoped PAT/OAuth token, catalog/schema; warehouse identity/state check, native metadata SQL, reviewed SQL statement, asynchronous state, INLINE JSON chunks fetched only through locally constructed endpoint paths, cancellation and exact typed result text. A warehouse must already report RUNNING; Harbor calls neither create nor start. The provider may change state between checks, so the execution review still discloses compute charges. INLINE is explicitly capped at16MiB (below the provider's25MiB hard limit). Truncated manifests fail visibly. External object-storage URLs are never followed or sent credentials, and full-result streaming export is not advertised. Binary/complex fields retain provider text with their native type rather than assuming an undocumented encoding.

Both: table opening creates an inert quoted SQL draft. Query submission requires the exact profile name and review of warehouse, target and possible charges. Metadata browsing is explicitly disclosed as native SQL that may use warehouse compute. Row/display limits do not cap compute cost. TLS/hostname verification is mandatory; arbitrary/private aliases, SSH and ambient credentials are unsupported. No automatic replay follows an uncertain write. If submission acknowledgement is lost, the local submission ID remains visible and cancellation is explicitly unconfirmed without a native handle. No result or credential is persisted through this adapter. Existing OS-protected credential/session behavior and workspace draft identity remain in force.
