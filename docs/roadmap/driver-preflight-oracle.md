# Oracle driver and local verification boundary

## Driver, architecture and licensing

- Runtime dependency: `oracledb@7.0.1`, pinned exactly. Types: `@types/oracledb@7.0.3` (development only). The Node driver is dual Apache-2.0 / UPL-1.0; the type declarations are MIT. Dependency installation used `--ignore-scripts`.
- Harbor uses the driver's default pure JavaScript **Thin** mode, with no `initOracleClient()` and no Instant Client installation. It rejects an already initialized Thick runtime. Thin requires Oracle Database 12.1 or newer. Only the explicitly tested fixture version below receives an integration claim.
- SQL username/password authentication with an explicit host, port and service name is supported. `profile.database` is an Oracle **service name**, default `FREEPDB1`; it is not a pluggable-database switch. An existing physical session cannot change services. Blank/default `public` schema resolves the authenticated current schema. An explicit schema preserves its exact case.
- SYSDBA, external/OS authentication, IAM/OAuth, TNS aliases, external configuration providers, RAC/failover, Autonomous Database wallets, proxy users and Thick authentication modes are not advertised. There is no automatic reconnect, transaction restoration, or write replay.
- Direct TCPS always verifies certificates and the original hostname. System trust works without a wallet. Custom trust requires a complete PEM CA + client certificate + private-key file because driver 7.0.1 uses its wallet content as certificate, key and trust material. CA-only configuration and disabled verification are rejected explicitly. Combined SSH + TCPS is rejected because the driver's hostname verifier cannot be safely redirected from the local forwarding socket. Trusted SSH + TCP uses the existing fingerprint-verified transport.
- Packaged Electron behavior on each release platform remains a separate acceptance gate. Driver compatibility is not installer verification.

Primary references: [Thin installation requirements](https://node-oracledb.readthedocs.io/en/latest/user_guide/installation.html), [driver license](https://github.com/oracle/node-oracledb/blob/v7.0.1/LICENSE.txt), [connection handling](https://node-oracledb.readthedocs.io/en/latest/user_guide/connection_handling.html), [connection API and cancellation](https://node-oracledb.readthedocs.io/en/latest/api_manual/connection.html).

## Implemented behavior and limits

- Each query tab owns a native standalone connection. Explicit transactions remain on that physical connection; closing a tab rolls them back. Native `connection.break()` cancels the matching running request. Both the driver's per-round-trip `callTimeout` and a query deadline apply. A lost connection closes the tab session and leaves an uncertain transaction outcome; it is never silently replaced.
- Ordinary SQL executes one statement. Complete PL/SQL units retain internal semicolons and accept an optional final SQL*Plus slash. Current-statement inference is rejected for PL/SQL; use explicit selection or one complete script unit. Every PL/SQL unit requires connection-name confirmation. DDL and PL/SQL are blocked inside an open user transaction because implicit commits or program transaction control could invalidate that boundary. SQL*Plus directives, OUT binds and implicit result cursors are not supported. Compilation warnings are reported rather than counted as successful program compilation.
- Read-only profiles combine a conservative lexical guard with native `SET TRANSACTION READ ONLY`. Stored functions can have privileged autonomous side effects; untrusted SQL still requires an appropriately restricted server account.
- Native NUMBER uses the Thin driver’s exact text representation. Binary float/double use round-trippable JavaScript numeric text. **Raw DATE/TIMESTAMP result columns are rejected**: Thin fetch-as-string internally uses JavaScript Date and loses sub-millisecond precision and original timezone identity. Table browsing uses explicit server TO_CHAR projections, preserves native column-type labels, signed BC years and up to9 fractional digits. TIMESTAMP WITH TIME ZONE includes exact offset and native region in brackets (for example `+01:00 [EUROPE/LONDON]`). Custom SQL/export must explicitly project date/time columns; no query is automatically rewritten or replayed. TIMESTAMP WITH LOCAL TIME ZONE browsing uses the explicitly configured UTC session zone. RAW/BLOB values use typed base64 cells. CLOB/BLOB reads use bounded public getData slices with an8MiB serialized-row cap. CLOB slices stay as strings until concatenation so supplemental Unicode characters split between UTF16 offsets are preserved; per-piece UTF8 conversion is avoided. Native JSON, object, vector, LONG and cursor columns require an explicit SQL projection to supported scalar types; they are not converted through lossy JavaScript objects. [Oracle format models](https://docs.oracle.com/en/database/oracle/oracle-database/26/sqlrf/Format-Models.html)
- Named numeric parameters bind exact text with native `TO_NUMBER`; timestamp parameters preserve up to 9 fractional digits with explicit native conversion. SQL text and values remain separate. Driver errors are reduced to static guidance and a validated error code; private values are not echoed.
- Native ALL_* catalogs provide owner-scoped objects, columns, ordered primary/foreign keys, indexes and constraints. Server DDL comes from DBMS_METADATA when account privileges permit it. Default expressions are available in server DDL; column metadata currently uses generated/identity markers rather than fetching unbounded LONG defaults. Unsupported or inaccessible metadata is not invented.
- Loaded results are limited by row count and 8 MiB. Full exports use fresh dedicated read-only transactions and native result-set batches capped by declared scalar byte widths; each row awaits the destination sink. LOB values have a separate byte cap. Exports exclude uncommitted tab work, use the common partial-file/finalization safeguards, and never rerun mutations.
- Imports use a dedicated connection, exact target review and per-batch transactions. Up to 500 rows / 8 MiB are allowed per batch. A row-share table lock protects metadata during each batch; mapped column types are revalidated before inserts. NUMBER and timestamp precision are checked before dispatch. Timestamp imports currently accept AD ISO values with offsets; destinations without explicit timezone require UTC. BC years and bracketed named-region exports need an explicit reviewed SQL conversion or text destination, rather than silent region/era loss. Empty Oracle strings become NULL and that warning is returned to the import UI. A failed batch is acknowledged as rolled back only after rollback succeeds; lost commit acknowledgements remain uncertain and are never replayed.
- Row-grid editing, execution plans, privileged diagnostics, automatic DDL generation, distributed transactions and managed-cloud deployment modes are not enabled by this adapter.
